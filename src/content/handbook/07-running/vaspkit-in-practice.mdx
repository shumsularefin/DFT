<Why>

VASPKIT is a free command-line helper that prepares VASP inputs and processes outputs. It removes much of the typing: a template `INCAR`, a `KPOINTS` file for a chosen resolution, a band path, a primitive cell, a plotted band structure. Knowing what it does for you also tells you what to check by hand <Cite id="S-020" />.

</Why>

<Intuition>

VASPKIT is a menu. You type `vaspkit`, then a group number, then a three-digit task, and answer a few prompts <Cite id="S-042" />. The codes group by purpose (inputs, structures, k-paths, density of states, bands, charge and potential, elastic constants, optics), and the tables on this page follow those groups. This page is the site's single list of the codes; other pages link here.

<Callout variant="warning" title="Menu numbers change between releases">

Every code below is the one in the author's Workflow Handbook, which takes them from the VASPKIT 1.5 tutorials and feature list. Menus are renumbered and extended between releases, so if a number does nothing, check the menu of your installed version before you rely on it <Cite id="S-042" />.

</Callout>

</Intuition>

<TheMath>

<Level min="intermediate">

VASPKIT does not change the physics. It writes files from rules (templates, k-mesh resolutions, symmetry from the structure) and reads files you could read yourself.

The one number worth converting is the k-mesh resolution $r$ that task 102 asks for. VASPKIT gives it in units of $2\pi$/Å. VASP's own `KSPACING` tag is in Å⁻¹ and already includes the $2\pi$, so

$$\text{KSPACING} \approx 2\pi r.$$

A VASPKIT resolution of 0.03 is therefore a `KSPACING` of about 0.19 Å⁻¹ <Cite id="S-042" />. The [units reference](/reference/units/) converts other values.

</Level>

</TheMath>

The full command map, from the Workflow Handbook <Cite id="S-042" />. "Output" is what VASPKIT prints or writes in the folder.

**Five ways to run a task.** The interactive menu is the easiest way to learn. The other four let you script a task, here with 102 as the example <Cite id="S-042" />:

<VaspFile
  name="shell"
  code={`vaspkit                                   # interactive menus
vaspkit -task 102 -kpr 0.04               # command-line mode (vaspkit -help lists options)
echo -e "102\\n2\\n0.04\\n" | vaspkit         # piped answers, in menu order
(echo 102; echo 2; echo 0.04) | vaspkit
vaspkit < cmd.in                          # answers stored one per line in a file
# batch over sub-folders, e.g. print every band gap
for d in */; do (cd \$d && echo -e "911\\n" | vaspkit | sed -n '40p' | awk '{print \$4}'); done`}
/>

- **Piped answers and `cmd.in`** give the answers in the order the menu asks for them: 102, then 2 (Gamma-centred), then 0.04 (the resolution).
- **The batch line** runs 911 in every sub-folder and prints one band gap per folder. `sed -n '40p'` and `awk '{print $4}'` pick one line and one column of the printed summary, so compare them with the 911 output of your own release before you trust the list.

**The `~/.vaspkit` settings that matter** <Cite id="S-042" />:

| Setting                                         | Effect                                                                                                                                                               |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PBE_PATH`, `POTCAR_TYPE`, `RECOMMENDED_POTCAR` | Where your POTCAR library lives, which functional, and whether VASP's recommended datasets (`_pv`, `_sv` and so on) are used. Required for 102 and 103.              |
| `SET_INCAR_WRITE_MODE`                          | The default, `OVERRIDE`, replaces an existing `INCAR` when you run 101. Set `BACK-UP-OLD` or `BACK-UP-NEW` (which writes `INCAR.new`) to protect a hand-edited file. |
| `MINI_INCAR`                                    | `.TRUE.` writes INCARs without the explanatory comments.                                                                                                             |
| `SET_FERMI_ENERGY_ZERO`                         | `.TRUE.` (the default) shifts DOS and band energies so that the Fermi level is at 0.                                                                                 |
| `FERMI_ENERGY.in` (a file, not a setting)       | VASPKIT reads the Fermi level from `DOSCAR` unless this file exists in the folder; put your value on its second line to override it.                                 |
| `PYTHON_BIN`, `PLOT_MATPLOTLIB`                 | Let 211 and 252 draw `band.png` automatically.                                                                                                                       |
| `GW_POTCAR`                                     | `.TRUE.` picks the `_GW` datasets.                                                                                                                                   |

**Input generation (group 01).**

| Code      | What it does                                                                                                     | Output and notes                                                                                                                                      |
| --------- | ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 101       | `INCAR` template for one or more task codes (next table)                                                         | `INCAR`. Codes join into one string: `STMG`, `SRPU`, `STH6D3` (static HSE06 plus D3)                                                                  |
| 102       | `KPOINTS` for an SCF run: asks 1 (Monkhorst-Pack) or 2 (Gamma-centred), then the resolution in 2π/Å              | `KPOINTS`, and also `POTCAR`. Resolution 0 means Gamma only; low 0.06 to 0.04, medium 0.04 to 0.03, fine 0.02 to 0.01. 0.03 to 0.04 is usually enough |
| 103 / 104 | `POTCAR` with the default datasets / with datasets you choose (104 asks per element, for example `Ti_sv`, `O_h`) | `POTCAR`                                                                                                                                              |
| 105 / 106 | `POSCAR` from a CIF (no fractional occupancy) / from a Materials Studio `.xsd` file (keeps fixed atoms)          | `POSCAR`                                                                                                                                              |
| 107       | Reorder the elements in `POSCAR`                                                                                 | `POSCAR_REV`                                                                                                                                          |
| 108 / 109 | Generate all inputs in one go / check all input files                                                            | 109 fixes the `INCAR` and `POSCAR` format and checks that `POTCAR` matches `POSCAR`. Run it before every submission                                   |

**What the templates leave to you.** There is no meta-GGA code: add the `METAGGA` tags to an ST or SR template by hand (see [functionals](/handbook/05-practical-choices/functionals/)). The templates start from conservative defaults; the LR template, for example, has `PREC = Normal`, `LREAL = Auto` and `ENCUT` commented out. So always set `ENCUT`, `EDIFF`, `ISMEAR` and the spin (`ISPIN`, `MAGMOM`) yourself <Cite id="S-042" />. The handbook says the same of every INCAR it shows: the values are starting points, to be converged for your material.

Habits that protect you:

- **Run 109 before every submission.** It fixes the `INCAR` and `POSCAR` format and checks that `POTCAR` matches `POSCAR` <Cite id="S-042" />.
- **Set `SET_INCAR_WRITE_MODE`.** The default, `OVERRIDE`, replaces an existing `INCAR` when you run 101. Set `BACK-UP-OLD` or `BACK-UP-NEW` in `~/.vaspkit` to protect a hand-edited file <Cite id="S-042" />.
- **Read what it wrote.** A template is a starting point: check `ENCUT` against your `POTCAR`, and set `EDIFF`, `ISMEAR`, `ISPIN` and `MAGMOM` yourself.
- **VASPKIT never replaces your licence.** It reads your POTCAR library; it does not provide one.

<WhatChanges>

| If you change...         | ...in VASPKIT's output              | ...what to expect                                     |
| ------------------------ | ----------------------------------- | ----------------------------------------------------- |
| The resolution in 102    | The mesh density                    | Denser means slower; 0.03 to 0.04 is often enough     |
| The task code in 101     | A different template                | Different tags: check them against your job           |
| `SET_FERMI_ENERGY_ZERO`  | Energies on a shifted axis          | Plots are relative to the Fermi level                 |
| A `FERMI_ENERGY.in` file | The Fermi level comes from the file | Plots shift to your value instead of the `DOSCAR` one |
| `MINI_INCAR = .TRUE.`    | Templates without comments          | Shorter files, without the built-in explanations      |
| Your VASPKIT release     | Menu numbers and printed layout     | The same task may have another code                   |

Why use it: fewer typing errors. Why check the output: templates do not know your system. What happens if you skip the check: a tag left over from another task, such as `IBRION = 6` in a DOS run.

</WhatChanges>

<Mistakes>

<Callout variant="mistake" title="Overwriting a hand-edited INCAR with 101">

The default write mode, `OVERRIDE`, replaces the file. Change `SET_INCAR_WRITE_MODE` first <Cite id="S-042" />.

</Callout>

<Callout variant="mistake" title="Trusting a menu number from an old note">

Check the code in your own release's menu <Cite id="S-042" />.

</Callout>

<Callout variant="mistake" title="Running a template without reading it">

A leftover tag from another task is a common cause of a wrong run, and the templates leave `ENCUT`, `EDIFF`, `ISMEAR` and the spin to you <Cite id="S-042" />.

</Callout>

<Callout variant="mistake" title="Looking for a meta-GGA task code">

101 has none. Start from an ST or SR template and add the `METAGGA` tags by hand <Cite id="S-042" />.

</Callout>

</Mistakes>
