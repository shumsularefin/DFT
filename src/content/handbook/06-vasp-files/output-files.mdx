<Why>

A finished run leaves a folder full of files. Some are logs you read, some are the starting point of your next run, and some are large files you can delete. Knowing which is which tells you what to keep, what to copy to the next folder, and where to look when something goes wrong <Cite id="S-041" />.

</Why>

<Intuition>

Sort the files by what you do with them.

- **Restart from them:** `CONTCAR` (the latest geometry), `WAVECAR` (wavefunctions) and `CHGCAR` (charge density).
- **Read them to judge the run:** `OSZICAR` (a short log) and `OUTCAR` (the full log). The next topic shows how to read both.
- **Plot or analyse from them:** `DOSCAR`, `EIGENVAL`, `PROCAR`, `vasprun.xml`, `XDATCAR`.
- **Everything else** is for special jobs: molecular dynamics, Bader analysis, work functions and so on.

<TheMath>

Most energies in the output are for the whole cell, in eV. Divide by the number of atoms before you compare cells of different size, and use that per-atom value for the 1 meV rule of thumb <Cite id="S-042" />.

<Level min="intermediate">

`F` in `OSZICAR` is the free energy that includes the smearing term, and `E0` is the energy extrapolated to zero smearing. The two differ by roughly the entropy term, which is why a large gap between them (more than about 1 meV per atom) points to a smearing width that is too large for the system <Cite id="S-019" />. The checks in the output reader on this site mark that rule as a heuristic.

</Level>

</TheMath>

<InVasp>

The sixteen entries of the Field Handbook, shortened <Cite id="S-041" />:

| File          | What it holds                                                                           | Use it for                                    |
| ------------- | --------------------------------------------------------------------------------------- | --------------------------------------------- |
| `CHG`         | Charge density in a compact format                                                      | Visualisation only                            |
| `CHGCAR`      | The full, restart-quality charge density of the last electronic step                    | `ICHARG = 1` or `11` restarts, Bader, plots   |
| `CONTCAR`     | The latest geometry in `POSCAR` format                                                  | The structure you restart from                |
| `DOSCAR`      | Total DOS, plus projected DOS when `LORBIT` is set                                      | Density-of-states plots                       |
| `EIGENVAL`    | Band energies and occupations at every k-point                                          | Band structures                               |
| `IBZKPT`      | The symmetry-reduced k-point list VASP computed                                         | Hybrid band-structure `KPOINTS`               |
| `OSZICAR`     | A compact log of electronic and ionic convergence                                       | Watching a run live                           |
| `OUTCAR`      | The complete log: setup, every step, forces, stress, timing                             | Judging and debugging a run                   |
| `PCDAT`       | Pair-correlation function averaged over an MD run                                       | MD analysis                                   |
| `PROCAR`      | Band and orbital projections at every k-point (`LORBIT` of 10 or more)                  | Projected (fat) bands                         |
| `REPORT`      | Log of advanced MD and machine-learned force-field runs                                 | MD and MLFF runs                              |
| `vaspout.h5`  | All results in one HDF5 file (only if VASP was built with HDF5)                         | Reading with py4vasp                          |
| `vasprun.xml` | Machine-readable record of inputs, structures, energies, forces and DOS                 | Parsers that must not break on format changes |
| `WAVECAR`     | The wavefunctions: the most valuable restart file (binary)                              | `ISTART = 1`, GW, BSE, band-decomposed work   |
| `XDATCAR`     | The trajectory: positions at every ionic step                                           | Relaxation paths and MD                       |
| Other outputs | `AECCAR0` and `AECCAR2` (Bader), `LOCPOT`, `ELFCAR`, `PARCHG`, `WAVEDER`, screen output | Special analyses                              |

Three of the large files are controlled by tags: `LWAVE` and `LCHARG` decide whether `WAVECAR` and `CHGCAR` are written, and `LORBIT` decides whether `PROCAR` and the projected `DOSCAR` are <Cite id="S-041" />.

**Who reads each file.** The Workflow Handbook lists, for the files of a normal project, what is in each one and which program or VASPKIT task reads it <Cite id="S-042" />. The task codes are explained in [VASPKIT in practice](/handbook/07-running/vaspkit-in-practice/).

| File                 | What it holds                                                                                                                                 | Read by                                                         |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `OUTCAR`             | The full log: energies, forces, stress, magnetization per site, E-fermi, `NBANDS`, elastic and dielectric tensors, Born charges, phonon modes | `grep`, VASPKIT 203, almost everything                          |
| `OSZICAR`            | One line per electronic step (dE, d eps) and per ionic step (F, E0, `mag=`)                                                                   | A quick convergence check                                       |
| `CONTCAR`            | The final structure, in the same format as `POSCAR`                                                                                           | The next calculation's `POSCAR`                                 |
| `CHGCAR`             | The charge density (and the magnetization density if `ISPIN = 2`) plus the PAW occupancies                                                    | `ICHARG = 1` or `11` restarts, Bader, VESTA, VASPKIT 311 to 314 |
| `WAVECAR`            | The wavefunctions (large)                                                                                                                     | `ISTART = 1` restarts, hybrid runs started from PBE             |
| `DOSCAR`             | The total DOS and, with `LORBIT`, the site-projected DOS                                                                                      | VASPKIT 111 and 113                                             |
| `PROCAR`             | Band- and k-resolved orbital projections (`LORBIT = 11`)                                                                                      | VASPKIT 212 to 214 (projected bands)                            |
| `EIGENVAL`           | The eigenvalues at each k-point                                                                                                               | VASPKIT 211, 911 and 912                                        |
| `vasprun.xml`        | Everything in XML: DOS, eigenvalues, dielectric function, forces                                                                              | phonopy, pymatgen, VASPKIT 711, p4vasp                          |
| `IBZKPT`             | The irreducible k-points actually used                                                                                                        | Checking which k-points VASP used                               |
| `AECCAR0`, `AECCAR2` | The core and valence all-electron densities (written with `LAECHG`)                                                                           | The Bader reference density                                     |
| `LOCPOT`             | The local potential (written with `LVHAR` or `LVTOT`)                                                                                         | Work function, VASPKIT 426                                      |
| `ELFCAR`             | The electron localization function (written with `LELF`)                                                                                      | VESTA, bonding analysis                                         |
| `XDATCAR`            | The trajectory: every ionic step                                                                                                              | Inspecting a relaxation that wandered                           |

For a work function the handbook prefers `LVHAR`, which writes the electrostatic potential: it reaches the vacuum level faster than the total potential that `LVTOT` writes <Cite id="S-042" />.

</InVasp>

<WhatChanges>

| If you change...       | ...in the output                          | ...what to expect                                              |
| ---------------------- | ----------------------------------------- | -------------------------------------------------------------- |
| `LWAVE = .FALSE.`      | No `WAVECAR`                              | Smaller folder; the next run cannot restart from wavefunctions |
| `LCHARG = .FALSE.`     | No `CHGCAR`                               | A later `ICHARG = 11` band run has nothing to read             |
| `LORBIT = 11`          | `PROCAR` and a projected `DOSCAR`         | Orbital-resolved plots become possible                         |
| A run that stops early | `CONTCAR` still holds the latest geometry | You can restart from it                                        |

Why keep the right files: the next run reads them. Why delete the others: `WAVECAR` can be many gigabytes. What happens if you delete the wrong one: you recompute it.

</WhatChanges>

<Mistakes>

<Callout variant="mistake" title="Restarting from POSCAR instead of CONTCAR">

After a relaxation, copy `CONTCAR` to `POSCAR` before the next stage, or you repeat the work <Cite id="S-041" />.

</Callout>

<Callout variant="mistake" title="Turning off LCHARG before a band calculation">

The band step reads the charge density the SCF wrote. Keep `LCHARG = .TRUE.` in the SCF run (the workflow topic explains why).

</Callout>

<Callout variant="mistake" title="Reading numbers from a different file than you think">

`OSZICAR` shows `F` and `E0`, and `OUTCAR` has several energy lines (`TOTEN`, without entropy, sigma to 0). Name the line you are quoting.

</Callout>

</Mistakes>
