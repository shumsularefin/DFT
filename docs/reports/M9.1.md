## What was built
- **`scripts/mp/schema.json`** (draft 2020-12, shared). It has `$defs` for:
  - `current`, `manifest`, `index` (columnar, with symbol and space-group lookups), `shard`, `structure` and `summary`;
  - `x-budgets` (index 1.5 MiB, shard target 100 KiB, maximum 128 KiB, total 10 MiB, all gzipped);
  - `x-keywords`, the only keywords allowed.

  Value ranges live in the schema: `energy_above_hull >= 0`, `band_gap >= 0`, `nsites >= 1`, volume and density > 0, space group 1 to 230.
- **`scripts/mp/config.yaml`:**
  - the index and starter filters (mp-api argument names) and a `db_version` pin;
  - the licence and attribution (CC BY 4.0, to be confirmed, Q-009);
  - retries;
  - the element exclusions, as two lists that match pymatgen `is_noble_gas` and `is_radioactive` (Tc, Pm, Z >= 84; Bi kept).
- **`scripts/mp/requirements.txt`:** exact pins: mp-api 0.47.0, emmet-core 0.88.3 (the version that resolved; the planning note said 0.88.1), pymatgen 2026.10.24, pymatgen-core 2026.10.31, PyYAML 6.0.3 and jsonschema 4.26.0.
- **`scripts/mp/fetch.py`:**
  - **Queries:** two `summary.search` queries, the index fields and the starter fields with structure. Both use `MPRester(use_document_model=False)`, and the key is read only by mp-api from `MP_API_KEY`.
  - **Retries:** four attempts with doubling backoff.
  - **Version guard:** it stops if the served database version differs from the pin, because REST always serves the current version.
  - **Raw cache:** git-ignored, at `scripts/mp/.cache/raw-<version>.json`. It records the version, the query, the UTC date, the client and its version, and the mock flag.
  - **`--mock`:** synthetic documents, no network and no key.
- **`scripts/mp/mpdata.py`** (shared):
  - conversion (ids read as strings; see D-072);
  - rounding, building and greedy shard packing;
  - the validator;
  - the synthetic document generator: the structure-derived fields come from pymatgen on the kpaths test cells, and every property value is made up.
- **`scripts/mp/build_shards.py`:**
  - Real data go to `public/data/mp/<version>/` plus `current.json`. Mock data go to `.cache/mock-out/` and are always `synthetic: true`.
  - It validates right after writing, and refuses to overwrite without `--force`.
- **`scripts/mp/validate.py`:** validates every dataset under `public/data/mp/` and the `current.json` pointer.
- **`scripts/mp/make_sample.py`:** writes `public/data/mp/sample/`.
  - 30 entries (`sample-0001` to `sample-0030`); 18 starters in 3 shards, using a small target so several shards are tested.
  - `synthetic: true`, with an attribution that says the values are made up.
  - Reruns are byte-identical.
- **`src/lib/mp/`:**
  - `schema.ts`: types plus key lists;
  - `jsonSchema.ts`: an interpreter for the allowed keywords;
  - `validate.ts`: the same checks as Python, using Web Crypto SHA-256 and fflate gzip, through a reader function, so it works in the browser and in Node.
- **Deploy gate:**
  - `scripts/build/check-real-data.mjs` now takes `--dist`, scans every `manifest.json` under `data/mp/` and checks `current.json`.
  - `deploy.yml` deletes `dist/data/mp/sample` before the gate.
  - `.gitignore` covers `scripts/mp/.cache/`, and `.prettierignore` covers the data and the Python folder.

## Not done / deferred (be exact)
- **No real data.** Fetching needs the author's key. Index size for the default filter is estimated (about 27 gzipped bytes per row in a pessimistic simulation, so about 55,000 rows fit), not measured.
- **The Python tests are not in CI or `npm run verify`.** CI has no Python step; run them in a venv from `scripts/mp/requirements.txt`.
- **No UI.** The "Synthetic demo data" banner is M9.2's job, driven by `manifest.synthetic`. M9.2 must also handle a live site without `current.json`.
- **The mock client does not model mp-api's pagination or chunking.** Those are inside mp-api.

## For the author: run the pipeline
From the repository root, with Python 3.12 or newer:

```bash
python3 -m venv .venv-mp
```

```bash
source .venv-mp/bin/activate
```

```bash
pip install -r scripts/mp/requirements.txt
```

```bash
export MP_API_KEY=paste-your-key-here
```

```bash
python scripts/mp/fetch.py --config scripts/mp/config.yaml
```

```bash
python scripts/mp/build_shards.py
```

```bash
python scripts/mp/validate.py
```

Then:
- set `db_version` in `scripts/mp/config.yaml` to the printed version;
- confirm the licence and attribution (Q-009);
- commit `public/data/mp/current.json` and `public/data/mp/<version>/`.

Details and the failure table are in `scripts/mp/README.md`.
