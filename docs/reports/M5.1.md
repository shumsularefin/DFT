# M5.1 Symmetry (moyo), CIF and standardization

Status: done        Branch: claude/vigilant-newton-ws593b        PR: see docs/PROGRESS.md

## What was built
- Dependency `@spglib/moyo-wasm@0.21.0` (exact pin). Budget `lazyChunks.moyo` (string `analyze_cell`, 300 KB cap); `check-size.mjs` now also counts `.wasm` files (new unit test). Measured: wasm 270.5 KB gzipped, worker glue 4.5 KB, so about 275 KB, in line with the 277 KB estimate.
- `src/lib/crystal/elements.ts`: 103-symbol table (order checked against `src/data/atomic-masses.json`), `atomicNumber`, `symbolOf`, `elementFromLabel`.
- `src/lib/crystal/symmetry.ts`: `analyzeWith(api, structure, { symprec = 1e-4, setting })`, `analyze` (registered API), conversions for moyo's matrix layout (D-045), `toMoyoCell`/`fromMoyoCell`. `moyo-node.ts` loads the wasm in Vitest.
- `src/workers/symmetry.worker.ts` + `src/lib/crystal/symmetry-client.ts`: moyo is initialised with `init(wasmUrl)` inside a worker on the first request; no main-thread fallback. The e2e test shows no `.wasm` request before the button is pressed, exactly one after.
- `src/lib/crystal/standardize.ts`: `describeStandardization` gives a beginner headline, detail sentences (atoms N to M, new lengths and angles, why), the transformation matrix (rows are the new vectors in terms of the old; verified by a metric test on three cells), the origin shift and the conventional-to-primitive atom mapping (`mapping_std_prim`).
- `src/lib/crystal/cif.ts`: tokenizer (comments, single and double quotes, `;` text fields), `loop_` handling, uncertainties `5.64(2)`, `?` and `.`, both symmetry-operation tags, affine operation parser, asymmetric-unit expansion with periodic duplicate merging (1e-3), one result per data block, partial occupancy refused with a reason and a way forward, `writeCif` in P1 (space group only in a comment).
- `src/lib/crystal/io.ts`: `detectFormat`, `readStructure` for POSCAR/CONTCAR, CIF (block choice, warning when several) and XYZ (supplied cell, extended-XYZ `Lattice=`, or molecule in a box with a warning).
- Check page `/design/symmetry-check/` (`SymmetryCheck.tsx`) so the worker and the budget are exercised in a real build; it is a harness, not the finished UI (M5.5 and M10 own the real pages).

## Seekpath comparison (work-order requirement: list the differing cases)
Space group number and primitive atom count agree for all 39. The primitive-cell metric tensor `A A^T` agrees to 1e-6 for 29 and differs for these 10 (volumes agree for all 39, asserted):
`monoclinic_C2m`, `triclinic_P1bar`, `v_oA1_Amm2`, `v_oA2_Amm2`, `v_mC1_mclc1`, `v_mC2_mclc3`, `v_mC3_mclc5`, `v_aP2_tria`, `v_aP2_trib`, `v_aP3_trib`. These are A-centred orthorhombic, C-centred monoclinic and triclinic cells, where moyo and seekpath pick different (equivalent) primitive bases. I did not investigate the exact cause. Decision for M5.3: apply seekpath's own transformation (D-045).
