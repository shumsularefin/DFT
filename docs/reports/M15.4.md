## What was built
- `parseOutcar` now returns `elastic` (the last `TOTAL ELASTIC MODULI (kBar)` block; the clamped-ion `SYMMETRIZED` block is skipped): the matrix as printed, the matrix in Voigt order in GPa (`VASP_TO_VOIGT = [0,1,2,5,3,4]`, `KBAR_IN_GPA = 0.1`), and the largest asymmetry. A broken block gives a warning naming its line.
- `src/lib/mechanics/elastic.ts`: `symmetrize`, `invert6` (compliance), `symmetricEigenvalues` (Jacobi), `stability` (eigenvalues decide; `bornConditions` for cubic, hexagonal and tetragonal (I) explain), `vrhModuli` / `analyseElastic` (B and G Voigt, Reuss, Hill; E, nu, A^U), `soundAndDebye` / `soundAndDebyeForStructure` (v_l, v_t, v_m, theta_D from POSCAR density and atom count), `indicators` (Pugh, Poisson, Cauchy and Zener for cubic, Chen hardness that is `applicable: false` when negative; all `heuristic: true` with source ids), `crossCheckBulk` / `crossCheckWithEos` (B_Hill vs B0, 5 % default, Heuristic).
- Golden data: `tests/reference/elastic_reference.json` (pymatgen 2026.10.24, pymatgen-core 2026.10.31 `ElasticTensor`; numpy compliance and eigenvalues) for a cubic, a hexagonal and a triclinic mixed-sign tensor. `tests/reference/elastic/OUTCAR_triclinic` and `OUTCAR_reorder_nonsymmetric` were written in VASP order and read back by pymatgen `Outcar.read_elastic_tensor`. The generator works out the VASP-to-Voigt map from the component names and pymatgen's `reverse_voigt_map`, checks it against `Tensor.from_voigt`, and asserts that it equals the S-042 statement.
