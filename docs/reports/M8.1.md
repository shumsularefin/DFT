## What was built
- `build_shannon.py` exports pymatgen's Shannon table (pymatgen 2026.10.24) with coordination mapped to integers, `SQ`/`PY` kept as `geometry`, spin mapped to `HS`/`LS`/null. Run with `--date` for a reproducible `_meta.generated`.
- `shannon.ts` returns `{ ok: true, value, entry }` or `{ ok: false, reason, available }`. It never substitutes a nearest value. Spin is required when HS and LS both exist ("spin required", both options listed); geometry is required when several geometries share a coordination and no plain entry exists.
- Dataset is about 49 KB raw (4.4 KB gzipped), above the work order's "about 25 KB" estimate because every row is kept with both radii. It is imported only by code that needs it.

## Completeness
- Counts: 492 rows from pymatgen over 94 elements; 491 assignable plus 1 unassigned.
- **Eu anomaly:** pymatgen stores one Eu row (CN VII, ionic 1.01, crystal 1.15) under a blank oxidation-state key. The oxidation state was not guessed. The row is kept in `_meta.unassigned` and excluded from lookups (D-057). The Ln3+ coverage golden (Eu: VI, VIII, IX) agrees with this.
- Comparison with the original table (Acta Cryst. A32, 751) or the Imperial database: **not done** (network, Q-007). Recorded in Q-002.
