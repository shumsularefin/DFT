# M3.4 INCAR validation rules engine

Status: done        Branch: claude/vigilant-newton-ws593b        PR: see docs/PROGRESS.md

## What was built
- `src/lib/vasp/validate.ts`: `validate(ctx)`, `applyFix`, `formatIssue`, `ALL_RULES`. Pure, no DOM. Issues are sorted by severity, then rule id.
- `src/lib/vasp/rules/*.ts`: one file per group (magnetism, smearing, accuracy, ionic, dftu, functional, restart, bands, parallel), plus `types.ts` and `helpers.ts`.
- `src/lib/vasp/validate.test.ts`: 131 tests (a positive and a negative test and a fix test for each of the 33 rules, threshold tests, engine tests, false-positive suite).
- Context additions: `kpointsIsOpt` (true when the line-mode file is given as KPOINTS_OPT), needed to encode V026. `Issue.whyDetail` is the optional intermediate-level text.

## False-positive suite
Run on all 11 INCAR blocks of the Workflow Handbook, plus the +U and MAGMOM fragments merged into the static INCAR (13 contexts; structure atom counts follow MAGMOM, `semiconductor`, ENMAX 270). **No `error` on any.** Every warning or info:
- Route B INCAR: **V018 warn** (ICHARG = 11, d-element MAGMOM, no LMAXMIX). Expected, matches Q-019.
- Route B INCAR: **V025 info** (ICHARG = 11 reminder). Expected by design.

## Judgement calls and open items
See Q-029. In short: V010 uses NSW > 1 not NSW > 0 (the handbook says the default is -1 for NSW <= 1); V013 treats any NCORE value as set; the d and f element lists are standard chemistry, not from a handbook; V004 counts the full mesh because the irreducible count is not computed here (M4.5).
