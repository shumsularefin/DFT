# M6.3 Thompson-sampling policy

Status: done        Branch: claude/great-dijkstra-oj0kbx        PR: see docs/PROGRESS.md

## What was built
- `src/lib/learning/random.ts`: mulberry32, Box-Muller normal, Marsaglia-Tsang Gamma (with the boost for shape below 1), Beta.
- `src/lib/learning/policy.ts`: six arms, eligibility with a plain-language reason for each choice, the fixed guard rails, `choose` (Thompson sampling), `reward`, `updateArm`, `creditRetention`. The learner state records which arm introduced each question (`introducedBy`) so the retention bonus can be credited later.
- `src/lib/learning/simulate.ts` (tests only): simulated learners with hidden parameters; comparison with a uniformly random policy.
- `src/components/practice/HowThisWorks.astro`: the user-facing explanation (beginner level, badge "Heuristic", sources S-037, S-038, S-039, states that nothing leaves the device unless sync is on). M6.4 places it on `/practice/`.

## Simulation (50 learners, 200 steps each, modules 1 to 3 bank: 76 questions, 16 concepts)
Mean fraction of concepts truly known at the end:

| Seed | Thompson policy | Random policy | Difference |
|---|---|---|---|
| 1 | 0.6138 | 0.2963 | +0.3175 |
| 2 | 0.5663 | 0.2537 | +0.3126 |
| 3 | 0.5525 | 0.2537 | +0.2988 |
| 4 | 0.5625 | 0.2550 | +0.3075 |
| 5 | 0.5975 | 0.2925 | +0.3050 |

The test asserts only "policy >= random" for every seed. Caveat (D-053): the simulator's learning model is a design choice (a concept can be learned only once its prerequisites are known), and the random baseline has no "read the topic" action, so part of the gap comes from reading and from respecting prerequisites rather than from the bandit itself. The numbers show the engine is wired correctly, not how much real learners gain.
