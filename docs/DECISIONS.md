# Decisions

Format: ID, decision, why (with evidence), consequences. New decisions get the next free `D-nnn`. Entries D-001 to D-028 were made during planning (numbers are grouped by topic, not by time) and verified where marked. "Verified" means it was run or inspected in a sandbox on 2026-10-27; see `docs/verified-stack/`.

## Stack and tooling

**D-001. Astro 7 (static) with React islands and MDX, replacing the "Vite SPA with React Router" suggestion.**
Why: the site is mostly content (11 modules, many topic pages) with a few heavy interactive tools. A client-rendered SPA ships all content as JavaScript, needs extra work for per-page titles and crawlability, and threatens the 200 KB first-load budget and the Lighthouse 95 target. Astro prerenders every page to HTML, ships near-zero JavaScript on content pages, hydrates only the labs and tools, and lets the level switch work with CSS alone (D-011). Each tool is one island that behaves like an SPA inside its page.
Consequences: routes are files in `src/pages/`; cross-tool hand-off goes through `src/lib/handoff.ts` (D-012), not a router.

**D-002. Exact version pins and the incompatibilities found.** (Verified: build, test, typecheck, lint, Pagefind, Playwright, axe and Lighthouse CI ran with this set.)
- `astro 7.3.8`, not 7.4.x: 7.4.0 needs Node >= 22.22 and 7.4.2 needs >= 22.23.4, while cloud sessions run Node 22.22.0. 7.3.x needs >= 22.12.
- `typescript 6.0.3`, not 7: typescript-eslint 8.72 supports TypeScript < 6.1, and `astro check` refuses TypeScript 7.
- `eslint 10.13.0` without `eslint-plugin-jsx-a11y` (it caps at ESLint 9). Accessibility is enforced with axe-core in Playwright (G4).
- No `@vite-pwa/astro` (peer range stops at Astro 5). The PWA uses `workbox-build` in a post-build script (D-010).
- Astro 7 no longer ships the unified Markdown pipeline by default: install `@astrojs/markdown-remark` and configure `markdown.processor: unified({...})` (see `docs/verified-stack/astro.config.mjs.reference`).
- Astro 7's `astro preview` detaches into a background daemon when not attached to a terminal, so Playwright's `webServer` uses a small static server (`docs/verified-stack/serve.mjs.reference`) that also mimics Firebase's trailing-slash redirects. ESLint needs Node globals declared for config files and scripts. Both found by a dry run of M0.1 built from the reference files alone.
- `vitest 5.0.5`, `@playwright/test 1.64.1`, `@lhci/cli 0.15.1`, `pagefind 1.5.2`, `zustand 5.0.16`, `react 19.3.1`, `three 0.186.1`.
Consequences: do not "update to latest". Bumps happen only in a dedicated chore commit with the full verify run.

**D-003. Symmetry engine: `@spglib/moyo-wasm 0.21.0`** (MIT or Apache-2.0, wasm 746 KB raw, 277 KB gzipped, from the spglib project). The SPEC's "spglib WebAssembly" is satisfied by moyo, the Rust successor from the same project. It gives space group, Hall number, standardized conventional and primitive cells with transformation matrices, Wyckoff letters and operations, and a Spglib-compatible setting. It has no irreducible k-mesh function, so mesh reduction is implemented in TypeScript from the operations and tested against `tests/reference/pw_kmesh_reference.json` (spglib counts).

**D-004. Molecule mode: RDKit JS (`@rdkit/rdkit 2026.9.1`, wasm 7.4 MB raw, 2.4 MB gzipped, lazy) for 2D layout, sanitization/valence checking, SMILES and MOL I/O only.** Verified by inspecting `RDKit_minimal.d.ts` and the wasm symbols: this build has **no 3D embedding (ETKDG) and no MMFF/UFF force field**. The SPEC's "RDKit 3D force field cleanup" is therefore not possible as written. Decision: implement a small valence-geometry optimizer in TypeScript (bond lengths from covalent radii, VSEPR ideal angles, soft repulsion), labelled "rough starting geometry, not a quantum result". The 2.4 MB download happens only when the user opens molecule mode and is cached by the service worker. Under the stricter 360 MB/day reading of Spark limits (Q-006) that is about 150 first-time molecule-mode users per day; acceptable, to be re-checked at M11.1.

**D-005. Default k-path convention: HPKOT (Hinuma et al. 2017, as in SeeK-path), second convention Setyawan-Curtarolo (as in pymatgen and Materials Project). Both are required; the UI always names the convention.** Why: the author's Workflow Handbook states VASPKIT task 303 uses the SeeK-path algorithm, so HPKOT matches the author's own protocol (the v1 SPEC defaulted to Setyawan-Curtarolo). Evidence the choice matters: for plain fcc both conventions give the same coordinates for X, W, K, L, U but different paths, HPKOT `Γ-X-U | K-Γ-L-W-X` versus Setyawan-Curtarolo `Γ-X-W-K-Γ-L-U-W-L-K | U-X` (`tests/reference/kpaths.json`). Band structures along the two are not interchangeable without care. Q-013 asks the author to confirm VASPKIT's behaviour with one run.

**D-006. 2D scientific plots use D3 modules (`d3-scale`, `d3-shape`, `d3-axis`, `d3-selection`) rendering SVG,** so SVG export is exact and PNG export is a canvas rasterization of that SVG. uPlot (canvas only) is allowed only for plots with more than 10,000 points (dense DOS or bands), where PNG export is enough.

**D-007. 3D uses vanilla Three.js behind a small `SceneController` class per tool, not react-three-fiber.** Smaller bundle, geometry stays testable without React, one disposal path. Loaded lazily after a user action or when scrolled into view, with a "Start 3D" fallback card and a 2D SVG/Canvas fallback when WebGL is unavailable. Device pixel ratio capped at 2.

**D-008. Math is rendered at build time with KaTeX as MathML (`output: 'mathml'`)** via `remark-math` and `rehype-katex`. No client JavaScript, no KaTeX CSS, no math fonts. Verified. Check rendering in Chromium and WebKit in M1.2; if a formula renders poorly, switch that formula to `htmlAndMathml` and include only the KaTeX fonts it needs.

**D-009. Search: Pagefind** (static index built after `astro build`, loaded on first focus of the search box).

**D-010. PWA: `workbox-build` `generateSW` run by `scripts/build/sw.mjs` after the build.** Precache the shell and critical CSS; runtime-cache `/_astro/**` (CacheFirst), datasets (StaleWhileRevalidate), navigations (NetworkFirst with an offline page). Heavy WASM is cached only after first use.

**D-011. Levels (Beginner, Intermediate, Pro) are cumulative and implemented with a `data-level` attribute on `<html>`.** `<Level min="intermediate">` content shows at Intermediate and Pro; `<Level max="beginner">` shows only at Beginner (simplifications that the deeper levels replace). An inline script sets the attribute before first paint from `localStorage`; with no script the default is Beginner. The route never changes.

**D-012. State.** Zustand stores with a versioned `localStorage` wrapper (`src/lib/storage.ts`, all access in try/catch, renders correctly with storage unavailable). Cross-tool hand-off uses `sessionStorage` key `dft:handoff` carrying a typed discriminated union from `src/lib/handoff.ts`, plus a URL fragment for small shareable payloads.

**D-013. Adaptive engine: Bayesian knowledge tracing per concept, Elo/IRT difficulty, SM-2 spacing, Thompson sampling (Beta-Bernoulli with fractional rewards) to choose the next item.** FSRS was considered and rejected for now: its parameters cannot be verified offline and SM-2 is fully specified and testable. This is an adaptive heuristic, not trained reinforcement learning, and the UI says so.

## Science and data conventions

**D-014. Convergence criterion.** A series is converged at the smallest setting x_i such that every later point differs from x_i by no more than the threshold (default 1 meV/atom, adjustable; a difference exactly equal to the threshold counts as converged). This is stricter than "the next point is within threshold" and avoids declaring convergence on a flat spot.

**D-015. Default energy quantity for convergence plots: `energy(sigma->0)`.** The author's own scripts run `grep "energy  without entropy" OUTCAR | tail -1 | awk '{print $NF}'` (two spaces after "energy", exactly as OUTCAR prints it); that OUTCAR line ends with `energy(sigma->0) = <value>`, so `$NF` is the sigma-to-zero energy. The tool offers all three quantities (free energy TOTEN, energy without entropy, energy(sigma->0)) and defaults to the one the author's workflow actually uses.

**D-016. K-mesh from KSPACING or resolution uses `ceil(|b_i| / spacing)` by default (|b_i| is the reciprocal lattice vector length including the factor 2 pi, as KSPACING is defined; VASPKIT's resolution r corresponds to spacing 2 pi r),** with the other plausible rounding rules available behind an interface and tested, until the author runs the calibration in Q-004. Ceil never under-samples. The UI always shows the resulting mesh so the user can see and override it.

**D-017. VASP target: 6.x, reference 6.4.x, noting where 5.4 differs,** exactly as the author's handbooks do ("VASP 5.4 / 6.x"). Every INCAR validation rule states the version it applies to.

**D-018. The author's two handbooks (`docs/source-material/`) are the content seed.** Their "Corrected" entries (the `fixed` records) override the original notes. Content derived from them is rewritten in the site's voice, keeps their VASP-wiki citations, and is never copied verbatim in bulk. One erratum has already been found in them (odd versus even Monkhorst-Pack meshes, Q-017), so they are a verified seed, not an oracle: every rule derived from them still needs its test.

**D-025. Shannon radii dataset: built from pymatgen's bundled table (MIT-licensed code, data from Shannon 1976),** then compared with 34 textbook anchor values, which all agree (`scripts/reference/gen_perovskite_reference.py`). This is a consistency check, not an independent verification: the planner wrote the anchor values from memory of the widely tabulated Shannon table, but had already seen several of them printed from pymatgen. An independent check against the original table is still required (Q-002). Completeness (the table has 492 entries) and licensing are still open (Q-002). Ionic radii (not crystal radii) are used for t, mu and tau.

**D-028. Rare-earth A-site coordination.** Shannon lists CN 12 for Ln3+ only for La, Ce, Nd, Sm; CN 9 and CN 8 exist for all of La to Lu. The family-trend view therefore needs an explicit, visible "A-site coordination policy" (CN 12 where available else flagged missing, or CN 9 for all, or CN 8 for all) and must never extrapolate silently. Golden sweeps for all three policies are in `tests/reference/perovskite_reference.json`.

## Process and platform

**D-019. Branching.** One branch and one PR per stage. Stages may be stacked (docs/WORKFLOW.md section 9). Merge commits, not squash, when stacked.

**D-020. Tests.** Vitest, test files next to the code (`*.test.ts`). Golden data in `tests/reference/`, regenerated only by `scripts/reference/*.py`. End-to-end with Playwright (`tests/e2e/`), `PW_CHROMIUM_PATH` for cloud sessions. Reference-generation scripts are pinned in `scripts/reference/requirements.txt`.

**D-021. Fonts: IBM Plex Sans (body) and JetBrains Mono (code and VASP files), self-hosted through Fontsource, latin subset, `font-display: swap`, with metric-matched fallbacks.** Matches the look of the author's Field Handbook. No requests to Google Fonts at runtime.

**D-022. The product name stays "DFT Handbook"** (working title; it is plain and searchable). The name lives in one place, `src/lib/site.ts`, so a rename is a one-line change.

**D-023. Lighthouse targets are measured per page class on mobile emulation:** content pages and tool pages must reach 95 or better in all four categories on initial load. 3D canvases and WebAssembly start only after a user action ("Start lab") or when scrolled into view and idle, which keeps main-thread work out of the measured load. If a tool page cannot reach 95 for performance with measured evidence, record the number and cause here and set a justified lower floor (not below 90). SEO is measured as described in D-027 until M11.3.

**D-024. Licence is undecided (Q-001).** Until the author decides, the repository has no LICENSE file and `THIRD_PARTY_NOTICES.md` records upstream licences. Ported MIT code (seekpath, pymatgen) must keep its copyright notice there.

**D-026. Firebase web configuration is not hard-coded.** `PUBLIC_FIREBASE_*` variables are injected at build time from GitHub repository variables. The site must build and work with none set (sync features hidden).

**D-027. Hosting.** `cleanUrls: true`, `trailingSlash: true` to match Astro `build.format: 'directory'`; hashed assets under `/_astro/` cached immutably for a year; HTML revalidated on every load; service worker never cached. `robots.txt` disallows all and pages carry `noindex` until M11.3 flips them, so half-built pages never get indexed. Consequence for Lighthouse: a `noindex` page always fails the SEO audit `is-crawlable`, so until M11.3 the SEO category is not asserted as a whole; the individual SEO audits (title, meta description, status code, link text, crawlable anchors, canonical, robots.txt validity, image alt) are asserted instead, and the report records the SEO score next to the note "noindex by design".

**D-028. Handbook content mechanics (M1.2).** Front matter schema lives in `src/lib/content-schema.mjs`, imported by both the Astro collection and `scripts/lint-content.mjs`, so build and linter cannot disagree. `<Level>` renders both branches with `data-visible` (computed by `visibleAt`) and CSS keyed on `html[data-level]` shows them with `display: contents`. Citation numbers are computed by the topic route from the MDX source (`citeOrder`) and passed through `Astro.locals.cites`, so numbering does not depend on render order. Topic MDX files import nothing: the route passes the anatomy components to `<Content components>`. Topics with no lab set `noLab: true` in front matter, the only way the linter accepts a missing `<Lab>`.


**D-029. Site chrome is vanilla TypeScript (M1.3).** `src/scripts/chrome.ts` wires the header, level switch, theme toggle, progress popover, search, sidebar ticks and shortcuts; state lives in three `zustand/vanilla` stores in `src/stores/` that persist through `storage.ts`. Controls that need JavaScript carry `.js-only` and stay hidden without it (`html.js` is set by the inline head script), so every page still reads fully with scripts off. Content pages ship about 3.5 KB gzipped JavaScript (budget 15 KB). `robots.txt` is generated from `INDEXING_ENABLED` in `src/lib/site.ts`, together with the robots meta tag. Nav entries for tools that do not exist yet link to their "coming soon" card on `/tools/`, so there are no dead links; `npm run links` checks every internal link and fragment in `dist/`.

**D-030. Lab framework lifecycle (M2.1).** `SceneController` takes its environment (document, matchMedia, observers, rAF, pixel ratio, clock) and optional renderer and controls factories, so its lifecycle is unit-tested without a GPU: listeners added equal listeners removed, `renderer.dispose()` runs once, and 20 open and close cycles leave zero live renderers. `Lazy3D` ties the scene to the running phase with an effect cleanup, so closing and unmounting both dispose it. Auto start needs motion allowed and the view on screen; a click always starts when WebGL exists (`shouldStart3D`). With reduced motion nothing loops and damping is off; the lab offers a Step button instead. The three chunk (about 135 KB gzipped with the demo scene and OrbitControls) is capped at 150 KB in `budgets.json` `lazyChunks`, matched by the string `WebGLRenderer`; an entry matching no file fails the check.

**D-031. Lab registry and page class for topics with a lab (M2.2).** `src/components/handbook/Lab.astro` maps a lab id to its React island (`client:visible`); unregistered ids still show the placeholder. `REGISTERED_LABS` and `topicPageClass` in `src/lib/topic.ts` make a topic with a registered lab an `island` page (200 KB budget) and every other topic a `content` page (15 KB). The cost-of-exactness lab plots relative cost only: Kohn-Sham DFT N^3 (S-049), HF N^4, MP2 N^5, CCSD N^6, CCSD(T) N^7 (S-048) as formal exponents, and the force-field and exact curves as labelled qualitative shapes with no number (Q-022). The size slider is log10 of the size multiple.

**D-032. Hydrogen orbital sampling in a worker (M2.3).** `src/lib/physics/hydrogen.ts` samples points from |psi|^2 with a seeded mulberry32 PRNG: inverse CDF on r from a 6000-cell table of r^2 R^2, then rejection on Y^2 with a 1.05 times bound (real harmonics up to l = 3 in Cartesian form). `OrbitalSampler` runs it in `orbital.worker.ts` (module worker, buffers transferred), drops superseded requests, and falls back to the main thread if a Worker cannot be created. The 3D lab (`OrbitalScene`) draws instanced-free `THREE.Points` with vertex colours (orange positive, blue negative); WebGL absent shows the radial probability plot. The box lab is a plain SVG with closed-form results; its playback is slowed by a printed factor against the femtosecond beat period and is not offered under reduced motion.

**D-033. 1D solver by bisection and inverse iteration; no worker (M2.4).** `src/lib/physics/solver1d.ts` finds the lowest k eigenvalues of the symmetric tridiagonal finite-difference matrix by Sturm-sequence bisection and the eigenvectors by inverse iteration with a pivoted tridiagonal solve (dgtsv-style) and Gram-Schmidt, so cost is O(k N) and no dependency is added. Measured here (Node, 8 states, mean of 5): 6.3 ms at 1200 points, 13.9 ms at 2000 points. That is well below one frame budget for a slider-driven lab, so the lab solves on the main thread and no worker was added (the work order asked to check; the check says it is not needed). The density-to-potential step uses the same discrete second derivative with psi = 0 at the walls, so the forward solve reproduces the density to rounding error; the lab prints "below 1e-6" instead of the raw rounding noise because it differs between Node and the browser and would otherwise cause a React hydration mismatch (error 418, found in e2e).

**D-034. Structure core is a pure library; masses from pymatgen's table (M3.1).** `src/lib/crystal/` has no DOM or React import (a test greps for it) and takes lattice rows as `Mat3` (row = lattice vector, `x = f A`). `parsePoscar` always returns fractional coordinates and a `wasCartesian` flag; a negative scale is a target volume. `guessCellType` reports the lattice metric class of the cell as given, not a Bravais lattice (fcc primitive gives `rhombohedral`); the symmetry stage (M5.1) owns real identification. `src/lib/handoff.ts` takes an injected `KV` store so it is tested without a DOM and validates every payload on receipt; a failed write returns false and does not navigate. `src/data/atomic-masses.json` comes from `scripts/reference/gen_atomic_masses.py` (pymatgen, S-034), unverified against IUPAC (Q-027). Coverage was not measured because `@vitest/coverage-v8` is not in the pinned stack; behaviour is covered by 70 tests listed in the report.

**D-035. KPOINTS library is pure and reports the rule it used (M3.2).** `src/lib/vasp/kpoints.ts` returns `{ mesh, rule, ratios }` so the UI can always say which rounding rule produced a mesh while Q-004 is open; the default stays `ceil` (D-016). `meshSymmetryRisk` is true only for even Monkhorst-Pack meshes on the hexagonal metric (a = b, alpha = beta = 90, gamma 120 or 60) and the fcc-primitive metric (a = b = c, all angles 60), the two cases the golden data measure; any other cell returns false meaning "not known", not "safe". `recommendCentering` makes a measured-breaking claim only for those two metrics. The Auto length formula is implemented as recalled and flagged (Q-018).

**D-036. Tag and preset data are generated from the handbooks, never typed twice (M3.3).** `scripts/build/extract-handbooks.mjs` reads the two handbook HTML files with Playwright, asserts exact record counts and writes `scripts/__generated__/*.json` (committed, deterministic). `scripts/build/build-vasp-data.mjs` merges those with the hand-written beginner and "what breaks" text into `src/data/vasp-tags.json` and `src/data/incar-presets.json`. Corrections (`fixed` records) override originals (D-018). A default the handbooks do not state is written as "Not stated in the handbooks" rather than filled from memory (Q-028).

**D-037. Validation rules are small objects in group files; absent tags use stated handbook defaults (M3.4).** Each rule has `id`, `title`, `severity`, `source`, `handbook`, `vasp` and `check(ctx, view)` returning hits; `validate` adds the metadata and sorts. A rule treats an absent tag as VASP's default only where the handbooks state that default (SIGMA 0.2, LMAXMIX 2, EDIFF 1E-4, NEDOS 301, ISIF 2, NSW 0, ALGO Normal); where they do not (AEXX, HFSCREEN) the rule stays silent. Fixes are pure functions returning a new INCAR.

**D-038. Input builder is one zustand store with pure selectors; downloads are gated, not hidden (M3.5).** `src/components/tools/input-builder/store.ts` holds all state and exports pure selectors (`issuesOf`, `kpointsOf`, `canDownload`, `shareOf`) so the checks always see the current k-point setting. File assembly, share encoding and job scripts live in `src/lib/vasp/builder.ts` and `jobscript.ts` (no DOM). Presets keep their documented placeholders (ENCUT, MAGMOM show as `<...>`) until the user fills them; the zip is blocked while any placeholder or validator error remains, unless the user ticks an explicit acknowledgement. The zip is built with fflate 0.8.3 (small, no extra dependency tree). The share link is a URL fragment (never sent to a server) and carries the structure only when it fits in 2 KB. NCORE and KPAR hints are labelled Heuristic. The relax preset's example MAGMOM is for a 6-atom cell, so a small cell shows V001 until the per-species helper rewrites it; V001 deliberately has no one-click fix because the right moments depend on the species.

**D-039. File explorer annotations are data from a pure library; OSZICAR and OUTCAR wait for M4.1 (M3.6).** `src/lib/vasp/annotate.ts` builds `Annotation` records (line, label, beginner, intermediate, pro, why, whatIf, tag, known) and never throws; an unreadable INCAR line becomes one annotation on that line. INCAR annotations reuse `vasp-tags.json`, so the text is the same as the input builder's tag cards. `FileExplorer` makes annotated lines buttons (arrows, Home and End move, Enter or click opens, Escape closes and returns focus); the button's name is its visible text plus a screen-reader-only "Line N: label" (axe `label-content-name-mismatch` rejects an aria-label that hides the visible text). MDX uses `<VaspFileExplorer kind code />` and `<PseudopotentialHeader />`, registered in the topic component map, so no import is needed. The header panel is named PseudopotentialHeader because the no-POTCAR guard rejects any file name starting with POTCAR. It states field meanings only, from the handbooks; ENMIN is left unexplained (Q-030).

**D-040. Output parsers are tolerant line scanners with key-value reading for OSZICAR ionic lines (M4.1).** `oszicar.ts` reads the ionic summary line as `KEY = number` pairs (`F`, `E0`, `d E`, `mag`, and the MD keys `T`, `E`, `EK`, `SP`, `SK`), so numbers glued to `=` and spin or non-spin forms need no special cases; a `T=` line sets `isMD`. Electronic lines are read as a solver label, a step number and the numbers after it, split with a regex that starts a new number at each sign, so fixed-width columns that touch still separate. `outcar.ts` applies one regular expression per item, records the source line, and returns `warnings` for anything absent; it never throws. `convergence.ts` implements D-014 exactly with a 1e-12 float allowance so a difference equal to the threshold counts as converged. See Q-031 for the `only-last-point` reading.

**D-041. Convergence series are generated as a virtual file tree and zipped in the browser (M4.2).** `series.ts` returns `{path, content}[]` for `00_conv/<run>/{POSCAR,INCAR,KPOINTS,job.sh}` plus `run_all.sh`, `collect.sh`, `make_potcar.sh` and `README.txt` at the top. ENCUT runs share one fixed mesh (default: VASPKIT resolution 0.04 for the loaded cell); k-mesh runs share one fixed ENCUT (default 1.3 x ENMAX). Runs are non-spin-polarised (ISPIN=1, no MAGMOM) unless the user switches spin on and has set MAGMOM per species. Series above 40 runs are refused. Scripts are stored with Unix mode 0755 in the zip. fflate's async `zip` (a worker) is used above 2 MB. `make_potcar.sh` only concatenates files from the user's `POTCAR_DIR`; no file or folder in the zip starts with POTCAR. The ENCUT-grid rule and the size threshold are in Q-032.

**D-042. The plotter renders SVG with React and uses only d3-scale and d3-shape (M4.3).** The work order lists four d3 modules; d3-selection and d3-axis would manipulate the DOM that React already owns, so axes, ticks and points are React elements and d3 supplies scales, tick generation and the line path. Added `d3-scale` 4.0.2 and `d3-shape` 3.2.0 (the 3.x family named in the verified stack for shape, 4.x for scale) and their `@types` as dev dependencies. A single editable table is the source of truth: files, CSV and typed rows all become rows, and file rows keep every energy quantity so changing the quantity re-reads them. Exports inline the computed colours and fonts so the SVG stands alone; PNG is drawn at 2x on a canvas. `parseSeriesLabel` now tries the file name and then its folders, and reads `kpt_6x6x6` as a mesh; `parseSeriesCsv` derives x from a label column when there is no x column, so `collect.sh` output can be pasted directly.

**D-043. Exact plane-wave counts by integer enumeration; the toy model is a 1D Kronig-Penney solver with a Jacobi eigensolver (M4.4).** `planewaves.ts` counts G with (hbar^2/2m)|G|^2 <= ENCUT by looping over integer triples inside rigorous bounds floor(kc|a_i|/2pi), so skew cells are exact; a relative 1e-12 allowance counts vectors on the sphere, and results match all 20 golden counts. The V kc^3/(6 pi^2) estimate is shown next to the exact count and the lab says why they differ. The toy model (`kp1d.ts`) diagonalises H(k) = (hbar^2/2m)(k+G)^2 delta + V(G-G') in a plane-wave basis with a small cyclic Jacobi solver (no dependency) and sums the two lowest bands at k = 0. A rectangular barrier (Kronig-Penney form, Fourier components v0 sin(pi m w/a)/(pi m)) is the default because its sharp edges converge slowly and make the curve visible; a smooth cosine is the contrast. The curve runs in a Web Worker with a main-thread fallback. The toy curve is badged Toy model and carries no real material numbers. The scaling hint (memory ~ N, work ~ N^1.5) is a labelled rule of thumb, not a runtime prediction.

**D-044. Lattice symmetry by Selling reduction plus 3^9 enumeration; irreducible points as classes joined by rotations that land on the mesh (M4.5).** `pointgroup.ts` Selling-reduces the basis (the four superbase vectors get pairwise non-positive dot products, tracked as integer combinations of the input basis), tries the 19683 integer matrices with entries in {-1, 0, 1} against the metric tensor (relative tolerance 1e-6) and maps the survivors back with `R_in = P^-1 R P`; orders match the holohedries (48, 48, 48, 24, 12, 16, 8, 4, 2) and are basis independent. `kmesh.ts` stores a mesh as (g + s)/n with s = 0 or 1/2 (Monkhorst-Pack shifts even n only, S-007), acts on k with the inverse transpose of R, adds time reversal, and joins two points when a rotation maps one onto the other and the image is itself a mesh point (union-find). This reproduces all 12 golden spglib counts for fcc Cu and all 32 golden symmetry booleans without special cases. The 2D tight-binding toy uses Gaussian smearing weight `erf(E / (sqrt(2) sigma))` and a series erf with only positive terms (S-053 table values in the test). Numbers shown in the lab are exact counts; the cell drawn is the reciprocal parallelepiped, not the Wigner-Seitz zone, and the notice says so.

**D-045. Symmetry through an injected moyo API, a worker for the browser, moyo's standard cell kept for now (M5.1).** `symmetry.ts` never imports moyo itself: it takes a `MoyoApi { analyze_cell }`, so Vitest loads it with `initSync` (`moyo-node.ts`), the browser worker loads it with `init(wasmUrl)` (`src/workers/symmetry.worker.ts`), and `registerMoyo` lets a host set a default for `analyze`. Verified conventions: `lattice.basis` is row-major, every other flat 3x3 from moyo is column-major (element (i, j) at i + 3 j), translations may be unwrapped (compare mod 1). The browser client (`symmetry-client.ts`) creates the worker on the first request and has no main-thread fallback, so the wasm is fetched only after the user asks for an analysis. CIF parsing and expansion live in `cif.ts`; partial occupancy is rejected rather than approximated. Against seekpath, moyo's standard primitive cell agrees on space group and atom count for all 39 golden structures but has a different primitive metric for 10; M5.3 must therefore apply seekpath's own transformation (list in docs/reports/M5.1.md).

**D-046. The Brillouin zone is cut by polygon clipping with a Delaunay-reduced basis; `reduction.ts` is the one place for basis reduction (M5.2).** `brillouinZone` starts from a box, clips every face polygon by the bisector plane of each candidate G (coefficients -2..2 of the reduced reciprocal basis, nearest first), then builds the cut face from the vertices lying on the plane, merges vertices at 1e-9 relative, and takes edges from the face loops and volume from tetrahedra to the origin. A plane that only touches an edge or vertex has no area and adds no face. `delaunayReduction` moved from `pointgroup.ts` to `reduction.ts` (re-exported there) instead of being duplicated. Ties in the Selling reduction are allowed, so a reduced vector may be a face diagonal; this does not matter because every Voronoi-relevant vector is a subset sum of any obtuse superbase.
