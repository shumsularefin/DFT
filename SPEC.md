## 1. Role and mission

Build a production-quality website that takes a complete beginner, with no quantum mechanics and no DFT background, to the point of running a sensible first VASP project, while offering real depth and genuinely useful research tools for intermediate and expert users.

Why it exists: the author struggled badly while learning DFT and VASP, and existing resources are scattered forum posts, old spreadsheets and visually dated utilities. The site explains not only what to do but why each step and parameter matters, what it changes, and what goes wrong when it is set badly.

Working name: **DFT Handbook** (D-022; one-line rename in `src/lib/site.ts`).

## 2. Audience and levels

Beginner (default): no quantum mechanics, plain language, analogies first, math behind expanders, every term defined on first use. Intermediate: students who run calculations and need parameters, convergence and analysis. Pro: researchers who want equations, full VASP tag tables, edge cases and literature pointers. A global switch changes depth, not the route, and is remembered. Levels are cumulative (D-011).

## 3. Hard platform constraints (Firebase Spark, no payment)

- Static hosting on Firebase Hosting. No Cloud Functions, no Cloud Storage for Firebase.
- Hosting storage 10 GB. Transfer is either 10 GB/month or 360 MB/day depending on source; unverified (Q-006). **Design for 360 MB/day**: per-visit transfer must stay small, immutable caching, lazy heavy assets, a service worker that avoids repeat downloads.
- Optional Firestore (about 1 GiB, 50K reads, 20K writes per day, unverified) and Firebase Auth only for progress sync. Everything works without signing in.
- All computation in the browser. User files (POSCAR, CIF, OUTCAR, OSZICAR, CSV) are parsed locally and never uploaded.
- First-load JavaScript under 200 KB gzipped on every page class (section 10 and `docs/ARCHITECTURE.md` section 8). Lazy-load 3D, WebAssembly and datasets. Content-hashed filenames, long cache headers and compression configured in `firebase.json`.
- Pages are `noindex` and `robots.txt` disallows all until M11.3 (D-027).

## 6. Research tools

### 6.1 Perovskite Tolerance Factor Explorer (M8)

Purpose: replace static tables and old spreadsheets with an interactive tool built on Shannon ionic radii.

- Pick A, B and X ions from a periodic table or searchable list. For each: oxidation state, coordination number (defaults A 12, B 6, X 6) and spin state where Shannon distinguishes them. Show the exact radius used and its source entry.
- Compute with explanations: Goldschmidt t = (rA + rX) / (sqrt(2)(rB + rX)); octahedral factor mu = rB / rX; Bartel tau = rX/rB - nA (nA - (rA/rB)/ln(rA/rB)), perovskite predicted when tau < 4.18. **The tau equation is unconfirmed against the paper (Q-003).** Use ionic radii, not crystal radii. Reference values: `tests/reference/perovskite_reference.json`.
- Checks and warnings: charge balance, unusual oxidation states (Cu3+ is "uncommon" not "invalid"), missing Shannon entries for a chosen coordination (never silent), heuristic limits of each factor.
- **Coordination policy.** Rare earths lack CN 12 radii except La, Ce, Nd, Sm. The A-site policy is explicit and visible: CN 12 where available else flagged missing; CN 9 for all; CN 8 for all (D-028).
- Stability maps: 2D t versus mu with labeled regions (boundaries from literature, Q-005), the composition as a point, plus a tau view. Mixed sites (A1-xA'x, B1-xB'x) use occupancy-weighted radii and oxidation states, labeled as a convention (Q-016).
- Family trend: fixed B and X, sweep A across La to Lu, plot t, mu and tau; golden sweep for three policies exists.
- Hand-off to Material Builder, Screening Studio and Input Builder.
- Data: compact static JSON of Shannon radii, source and version recorded, licence and completeness flagged (Q-002).
- UI is honest: tolerance factors are heuristics and do not guarantee stability.

### 6.2 VASP Input Builder and Convergence Helper (M3, M4)

- INCAR and KPOINTS generator with presets: relaxation, static, DOS, band structure, convergence test, spin-polarized, DFT+U, hybrid, vdW; plus elastic, optics and phonon as in the author's Workflow Handbook. The default flow follows the author's fixed protocol (reproduced faithfully in the content). Every tag has a plain-language card: what it does, why this value, default, typical range, what breaks if wrong, link to the handbook page. Level aware. **Target VASP 6.x, reference 6.4.x (D-017).**
- Smart validation: a rule engine where every rule has an ID, severity, plain explanation, optional one-click fix, a source (author's handbook entry or VASP wiki page by name), the VASP version, and tests. Rules are listed in M3.4. A rule without a source does not ship.
- KPOINTS builder: automatic meshes from KSPACING or resolution and the user's POSCAR lattice; Gamma versus Monkhorst-Pack guidance (even Monkhorst-Pack meshes break hexagonal and fcc-primitive symmetry, so the builder recommends Gamma-centred meshes there, Q-017); line mode via the k-path tool. The rounding rule is pending calibration (Q-004, D-016).
- Convergence series generator: user enters ENMAX (POTCAR is never needed or generated); proposes ENCUT and k-mesh series; produces a zip of ready folders (INCAR, KPOINTS, POSCAR, job script for SLURM or PBS, run and collect scripts) built in the browser.
- Convergence plotter: drop OSZICAR or OUTCAR files or paste CSV, parsed locally. Energy per atom (and pressure or forces when present) versus ENCUT or k-mesh, adjustable threshold band (default 1 meV/atom), automatic detection of the smallest converged value by D-014, plain-language explanation, a Pulay-stress warning (heuristic, Q-014), PNG and SVG export. Default energy quantity `energy(sigma->0)` (D-015).
- Never generate or host POTCAR content. Explain how users obtain POTCARs under their own licence.

### 6.3 Brillouin Zone and k-path Viewer (M5)

- Input: Bravais lattice with parameters, POSCAR or CIF drop, or hand-off from the Builder.
- Space group and standardized cell from moyo; labels and paths are valid only in the standardized setting, so convert first and tell the user exactly how the cell changed (transformation matrix, new parameters).
- First Brillouin zone by the Wigner-Seitz construction, rendered in 3D with rotation, zoom and touch; reciprocal vectors, labeled high-symmetry points, recommended path. **Conventions: HPKOT default, Setyawan-Curtarolo second, always named in the UI (D-005).**
- Animate travel along the path, overlay a k-point mesh, show segment lengths and point counts.
- Export a VASP line-mode KPOINTS (and a VASPKIT-style `KPATH.in`) with the chosen points per segment, and a plain coordinate list. Link to the band-structure module.
- Tests: zone geometry against `tests/reference/bz_geometry.json` (fcc truncated octahedron 24/36/14 vertices/edges/faces, bcc rhombic dodecahedron 14/24/12, hexagonal prism 12/18/8, volume = (2 pi)^3/V), paths against `tests/reference/kpaths.json`.

## 7. Adaptive learning engine (M6)

On-device adaptive tutor (true RL training is not feasible on the free plan, and the UI says so): Bayesian knowledge tracing and an Elo/IRT difficulty estimate per concept, SM-2 spaced repetition, Thompson sampling (Beta-Bernoulli with fractional rewards) choosing the next question, hint or topic, with rewards from correctness, time, hint use and retention (D-013). A concept dependency graph, a visible mastery map, and gentle gamification only (progress, streaks with rest days, milestones; no dark patterns). State local, with optional Firestore sync using batched, debounced writes.

## 8. Screening Studio (M9)

Goal: a beginner who learned DFT picks a sensible first project.

1. Explorer: filter by elements, energy above hull, band gap, application preset (solar, catalysis, batteries; presets are labeled filter bundles, not predictions), cost and toxicity flags only where a cited source exists (Q-011). Perovskite candidates link to the Tolerance Factor Explorer.
2. Feasibility check: Green, Yellow or Red from atoms per cell, heavy or f-electron elements, magnetism, PAW availability (Q-010) and rough compute time (order-of-magnitude buckets with stated assumptions), with the reasoning shown.
3. First project builder: starter project card with structure (POSCAR and CIF), suggested sequence (convergence test, relaxation, static, DOS), INCAR and KPOINTS from the Input Builder, expected runtime, and a sanity check comparing the Materials Project lattice parameters and band gap with the user's own result (with PBE-level caveats).

Data pipeline: offline Python script (mp-api client) run by the author with their own key; the key never enters the repo or the browser. Output is sharded static JSON (a compact filter index plus chunks by chemical system, a few MB gzipped total) with data version, date and attribution (Q-009). Builder-made **synthetic sample data** is clearly flagged, shows a banner, and a CI step blocks live deploys of synthetic data. A marked hook exists for an optional ML-estimated stability column.

## 9. Material Builder (M10)

Minimalist, ChemDraw-inspired editor; drag atoms from an interactive periodic table (with a keyboard and tap alternative). Two modes: molecule and crystal.

Validity engine (heuristic, fast, explained): valence and oxidation-state rules, charge neutrality (SMACT-style), electronegativity ordering; minimum distances from covalent and ionic radii; Pauling's rules for coordination; Goldschmidt tolerance factor for perovskites (shared code with 6.1); Hume-Rothery checks for alloys; overlap and periodic-boundary consistency; space group via moyo. Errors block export; warnings explain the concern; every message says why and offers a one-click fix. Absurd structures are never silently allowed.

Clean-up: crystals get symmetrize, standardize primitive or conventional cell, wrap atoms, merge duplicates, snap to ideal Wyckoff sites and gentle distance relaxation, with undo and redo. Molecules get a tidy 2D layout (RDKit) and a rough 3D starting geometry from the in-house optimizer (D-004), with undo and redo. Export POSCAR, CIF and XYZ; one-click hand-off to the Input Builder and k-path viewer. State openly that these checks are heuristics and do not replace DFT.

## 11. Design language

Modern, clean, minimalist. Generous whitespace, one restrained accent, light and dark themes, a clear type scale, IBM Plex Sans for reading and JetBrains Mono for VASP files (D-021). Subtle purposeful motion. Tab-style navigation and a persistent progress tracker. Genuinely interesting: surprising visuals, small delights, storytelling about why the physics matters.

## 12. Scientific accuracy and integrity

- Every VASP tag, default and behavior is cross-checked against the VASP wiki (by page name) and the author's handbooks; the VASP version is stated.
- Every formula, constant and table has a source ID in `docs/SCIENCE_SOURCES.md` and a unit test against a golden file or a cited value. The guard enforces that cited IDs exist.
- Unknowns go to `docs/OPEN_QUESTIONS.md` with an `it.todo`, never into guessed code.
- Write original explanations; never reproduce the Sholl and Steckel book or papers. Never host or generate real POTCAR content (guard).
- Keep a references page, a changelog and a visible disclaimer about ML and heuristic limits. Pages carry a review status (draft, review, verified).

## 13. Repository and workflow

- Folders: `src/`, `public/`, `scripts/`, `tests/`, `docs/` (`PROGRESS.md`, `OPEN_QUESTIONS.md`, `DECISIONS.md`, ...). Layout in `docs/ARCHITECTURE.md`.
- One branch and one pull request per stage. Conventional Commits. Process in `docs/WORKFLOW.md`; the single prompt that drives each session in `docs/KICKOFF_PROMPT.md`.
- GitHub Actions: guards, lint, typecheck, test and build on every pull request; Firebase preview channel for same-repo pull requests; deploy to Firebase Hosting on merge to `main` with the official action. Service account stored as a GitHub secret by the author (`docs/SETUP_FIREBASE.md`).
- Each session starts by reading `CLAUDE.md`, `SPEC.md`, `docs/WORKFLOW.md`, `docs/PROGRESS.md` and ends by updating `docs/PROGRESS.md` and writing its report.
